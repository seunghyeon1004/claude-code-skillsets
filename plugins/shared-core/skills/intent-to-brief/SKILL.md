# Intent to Brief

## Overview

Turn scattered intent into a compact working contract. Keep uncertainty visible so an inference never becomes an accidental requirement.

## Brief Contract

Record these fields and label each value `confirmed`, `assumption`, or `open`:

| Field | Question |
| --- | --- |
| Goal | What outcome should change? |
| Deliverable | What concrete artifact or action is expected? |
| Audience | Who will use or judge it? |
| Inputs | Which materials and facts may be used? |
| Constraints | What limits scope, format, timing, cost, or access? |
| Completion | What observable evidence means done? |

Add an explicit out-of-scope line when nearby work could expand the request.

## Workflow

1. Extract confirmed values from the request and source material.
2. Label useful inferences as assumptions, not facts.
3. Mark missing values open.
4. Ask one focused question only when an open value changes the execution path or acceptance decision.
5. Proceed with confirmed work and preserve the labels in the final handoff.

## Confirmation Rule

Label a field `confirmed` only with a direct, explicit exact value. Explicit negative
evidence wins: when a field is explicitly unstated, mark it `open`; indirect context
cannot override that. Someone who
"knows the context" does not confirm that person as the audience. An artifact family
does not confirm the exact deliverable; "launch brief" still leaves format and
acceptance boundary. Put useful contextual guesses under `assumption`; never upgrade
them to confirmed to preserve momentum.

## When Not to Use

- The request already provides an unambiguous deliverable and observable acceptance criteria.
- The task is a direct factual question with no artifact or workflow to define.
- Workspace discovery is the real gap; establish workspace context first.

## Common Mistakes

- Repeating source notes instead of defining the intended outcome.
- Inventing an audience or approval standard to keep moving.
- Using vague completion language such as "high quality" or "looks good."
- Turning every unknown into a blocker instead of identifying path-changing ones.
